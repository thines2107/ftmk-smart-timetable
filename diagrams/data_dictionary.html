Overview
Database structure summary — 5 core tables

The FTMK Smart Timetable Arrangement System uses a relational database with 5 core tables. The database stores user accounts, master timetable data extracted from faculty PDFs, student-saved timetable combinations, social friend links, and lecturer profile information.

# Table Name Description No. of Fields
1 users Stores all system user accounts (admins and students) with authentication and academic profile data. 10
2 timetable Master timetable data extracted from faculty PDF uploads. Each row is one class session. 11
3 saved_timetables Stores timetable combinations that students have saved to their profile, including a primary flag. 6
4 saved_friends Stores friend relationships between students for social timetable comparison. 5
5 lecturer_profiles Stores lecturer contact and office information, populated by web scraping the faculty staff directory. 7

Table: users
Stores all registered system users — administrators and students
users

Contains authentication credentials and academic profile information for every registered user in the system.

Data Element Description Data Type Size Example
id Unique identifier for each user. Auto-incremented by the database. INTEGER — 1, 2, 3
name Full name of the user as provided during registration. VARCHAR 100 Ahmad Syahmi bin Ali
email User's email address. Must be unique across all accounts. VARCHAR 120 B032210001@student.utem.edu.my
password_hash Werkzeug-hashed password string (scrypt). Never stores plain-text password. VARCHAR 256 scrypt:32768:8:1$abc...
role Role of the user in the system. Determines access level and portal shown after login. VARCHAR 20 student, admin
username Unique login username chosen by the student during registration. Used at login. VARCHAR 50 syahmi2024
matric_no Student's matriculation number. Used in social features and classmate matching. VARCHAR 50 B032210001
year Student's current year of study. VARCHAR 20 Year 1, Year 3
course Programme code the student is enrolled in. VARCHAR 50 BITA, BITC, BITP
group_name Student's assigned class group. Used for classmate matching features. VARCHAR 50 S1G1, S2G3

Table: timetable
Master timetable data extracted from faculty PDF uploads
timetable

Each row represents a single class session — one subject, one group, one time slot. Populated by the PDF extraction module triggered by the Admin.

Data Element Description Data Type Size Example
id Unique identifier for each timetable record. INTEGER — 1, 42, 305
course_code Programme code this class session belongs to. VARCHAR 50 BITA, BITC, BITP
semester Semester and academic session label as extracted from the PDF. VARCHAR 50 Semester 2 Session 2025/2026
group_name Class group identifier for this session. Differentiates parallel groups of the same subject. VARCHAR 50 S1G1, S2G3
subject_code Subject code as defined by the faculty curriculum. VARCHAR 50 BITP1123, BITU3973
subject_name Full descriptive name of the subject. Propagated globally if updated by admin. VARCHAR 200 Programming Technique
class_type Type of the class session — Lecture or Laboratory. VARCHAR 50 LEC, LAB
day Day of the week on which the class is held. VARCHAR 20 MONDAY, FRIDAY
start_time Class start time in 24-hour format. Used for schedule conflict detection. TIME — 08:00:00, 14:00:00
end_time Class end time in 24-hour format. Used for schedule conflict detection. TIME — 10:00:00, 16:00:00
room Assigned classroom or laboratory room code. May be TBA if not yet assigned. VARCHAR 100 BK11, BR09, Lab3
lecturer_name Name of the assigned lecturer for this session. Linked to lecturer_profiles via fuzzy matching. VARCHAR 200 DR. AHMAD FADZIL BIN ISMAIL

Table: saved_timetables
Student-saved timetable combinations generated by the Genetic Algorithm
saved_timetables

Each row is one timetable combination a student has saved. The full schedule is stored as a JSON string. One record per student may be flagged as Primary.

Data Element Description Data Type Size Example
id Unique identifier for each saved timetable record. INTEGER — 1, 5, 12
user_id References the student who saved this timetable. Foreign key to users table. INTEGER — 3, 7
name User-defined label for this saved timetable combination. VARCHAR 100 My Sem 2 Timetable
data Full timetable combination stored as a JSON string — includes subject, group, day, time, room details. TEXT — [{"subject": "BITP1123", "group_name": "S1G1", ...}]
is_primary Flag indicating whether this is the student's primary timetable. Used in social and analytics features. BOOLEAN — True, False
created_at Timestamp when this timetable was saved. Auto-set by the database. DATETIME — 2025-06-10 14:30:00
5
Table: saved_friends
Social links between students for timetable comparison
saved_friends

Records a friend link from one student to another, identified by matric number. Used to overlay timetables and find common free time slots.

Data Element Description Data Type Size Example
id Unique identifier for each friend relationship record. INTEGER — 1, 3, 8
user_id The student who added this friend. Foreign key to users table. INTEGER — 2, 5
friend_matric Matric number of the added friend. Used to retrieve the friend's primary timetable for comparison. VARCHAR 50 B032210045
friend_name Full name of the friend at the time they were added. Stored for display purposes. VARCHAR 100 Nurul Ain binti Razak
created_at Timestamp recording when this friendship link was created. DATETIME — 2025-06-10 09:15:00
6
Table: lecturer_profiles
Lecturer contact and office info — populated via web scraping the FTMK staff directory
lecturer_profiles

Stores official lecturer profile data scraped from the FTMK staff directory website. Linked to timetable records at runtime via fuzzy name matching (confidence threshold > 80%).

Data Element Description Data Type Size Example
id Unique identifier for each lecturer profile record. INTEGER — 1, 10, 24
name Full name of the lecturer as scraped from the official staff directory. Used as the matching key against timetable.lecturer_name. VARCHAR 200 DR. AHMAD FADZIL BIN ISMAIL
title Academic or professional title of the lecturer. VARCHAR 100 Dr., Prof., Ts. Dr.
email Official UTEM email address of the lecturer. VARCHAR 120 fadzil@utem.edu.my
department Department or centre within FTMK that the lecturer belongs to. VARCHAR 100 Dept. of Software Engineering
block Building or block where the lecturer's office is located. VARCHAR 50 Block A, Block B
office_room Specific room number or code of the lecturer's office. VARCHAR 100 B1-17, B2-09
